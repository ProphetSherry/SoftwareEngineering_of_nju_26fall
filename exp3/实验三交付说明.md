## 2. UML 到实现的对应

| 实验二设计 | 实现实例 | 验证方式 |
| --- | --- | --- |
| 用户及四种角色 | `users` 表；`Service::Login`、`Require`、`Own`；`Window::Shell` 按角色建立导航 | 登录、越权、账号停用和归属隔离测试 |
| 活动、场次、票种、座位 | `events`、`sessions`、`tickets`、`seats`；完整草稿编辑与保存 | 多场次、多票种、容量和重复座位测试 |
| 发布版本与审核申请 | `versions`、`reviews`、候选配置表；提交、批准、拒绝及撤回 | 审核前隔离、批准后生效、撤回和失败回滚 |
| 报名状态图 | `registrations.status`；`Register`、`Transition`、`Cancel`、`Promote`、`Receive`、`CheckIn`、`Tick` | 候补、待付款、已报名、取消、签到及缺席场景 |
| 线下实收与退款任务 | `receipts`、`refunds`；`Receive`、`AbnormalReceipt`、`CompleteRefund` | 实收金额、正常退款、异常实收和重复确认拒绝 |
| 检票分配与首次签到 | `assignments`；`Assign`、`CheckerConflict`、`CheckIn` | 分配隔离、排班冲突、签到时间与重复签到 |
| 取消释放名额与原票种递补时序 | `Cancel` 在事务中修改状态并调用递补；成功请求和日志随业务提交 | 候补顺序、票种隔离、并发抢位和日志故障回滚 |
| 定时任务、查询、日志和备份组件 | `Tick`、`Registrations`、`Statistics`、`ExportCsv`、`Logs`、`Backup` | 超时、截止清理、座位、CSV、日志权限和恢复读取 |

实现采用三层桌面原型：`Window/CLI → Service → Database`。UML 中的领域对象并未全部实现为同名 C++ 实体类，而是通过 SQLite 表和 `Row/Rows` 表达。编号使用数据库整数，金额使用整数分，时间使用 Unix 秒。组件图中的 HTTP API 当前由本地函数调用替代；并发采用 SQLite 写事务串行化，并非逐行锁。站内通知已实现，外部通知渠道和经认定的特殊退款流程尚未实现。这些差异在使用说明第 12 节明确列出。
