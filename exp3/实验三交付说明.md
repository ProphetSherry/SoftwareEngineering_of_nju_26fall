## 2. UML 设计与代码实现对应

| 设计内容 | 实现位置与方式 | 验证内容 |
| --- | --- | --- |
| 用户与四类角色 | users；Service::Login、Require、Own；Window 角色工作台 | 登录、停用、越权及组织者归属隔离 |
| 活动、场次、票种与座位 | events、sessions、tickets、seats；完整草稿配置与保存 | 多场次、多票种、容量与重复座位 |
| 发布版本及审核申请 | versions、reviews 及候选配置；提交、批准、拒绝、撤回 | 审核前隔离、批准生效、撤回与失败回滚 |
| 报名状态图 | registrations.status；Register、Cancel、Promote、Receive、CheckIn、Tick | 候补、待付款、已报名、已取消、已签到、缺席 |
| 线下实收与退款 | receipts、refunds；Receive、AbnormalReceipt、CompleteRefund | 金额核验、异常实收、全额退款与重复确认拒绝 |
| 检票分配及首次签到 | assignments；Assign、CheckerConflict、CheckIn | 时间冲突、分配隔离、时间门禁与重复签到 |
| 取消与原票种递补时序 | 同一事务取消、释放名额、递补及写日志 | 候补顺序、票种隔离、并发抢位和故障回滚 |
| 查询、日志、通知及后台任务 | Registrations、Statistics、ExportCsv、Logs、Tick、Backup | 活动场次筛选、CSV、权限、超时、排座、缺席及备份读取 |

实现分为界面/CLI、Service、Database 三层。UML 实体以关系表和 Row/Rows 表达，没有逐一建立同名 C++ 类；编号使用数据库整数，金额使用整数分。组件图中的 HTTP API 在本地原型中由函数调用替代，数据库并发采用 SQLite 写事务串行化。站内通知已实现，外部通知和经认定的特殊退款流程未完成。这些实现差异不应描述为完整的联网部署能力。
